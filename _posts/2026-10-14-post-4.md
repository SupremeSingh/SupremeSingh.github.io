*Part 4 of Building a Cheaper Critic · 14 November 2026*

A language model might use several tokens to write “subtract three from both sides.” To a reader, this is one mathematical move. To a token-level critic, it can be several separate training states with closely related features and the same observed final outcome.

Do we need to fit on all of them?

Chunking asks us to choose a coarser unit: a line, a sentence, a fixed token group, or a detected reasoning step. The immediate opportunity is to reduce fitting work. Whether predictions improve is a different question.

## 1. A chunk groups actions; it does not erase them

For the question “Solve $$2x+3=11$$,” imagine this answer:

| Chunk | Generated text | State before the chunk |
|---|---|---|
| 1 | Subtract three: $$2x=8$$. | Question only |
| 2 | Divide by two: $$x=4$$. | Question and chunk 1 |
| 3 | Therefore the answer is four. | Question and chunks 1–2 |

The actor still generates individual tokens. Chunking selects which prefixes the critic fits or scores. The state before chunk 2 must contain only the text already written, not chunk 2's calculation.

Reasoning-boundary tools are heuristics. A newline may separate ideas, split one idea or contain several. A usable implementation must preserve original token IDs, cover every action exactly once and have a defined fallback when alignment fails.

## 2. Count the work that actually disappears

Suppose $$N$$ answers contain an average of $$T$$ tokens and $$C$$ chunks. A token head fits roughly $$NT$$ states; a boundary head fits roughly $$NC$$. The reduction is

$$
\frac{\text{token fitting states}}{\text{chunk fitting states}}
\approx\frac TC.
$$

For an illustrative 900-token answer divided into 45 chunks, this is 20 times fewer fitted states. It is not automatically 20 times less training time.

For $$m$$ features, dense Ridge accumulation costs approximately $$O(NTm^2)$$ or $$O(NCm^2)$$. But the solve remains $$O(m^3)$$ in both cases, and the statistics matrix remains $$O(m^2)$$. Chunking reduces the number of examples, not the width of the fitted system.

A frozen encoder may still process the complete answer to obtain boundary features. The actor still generates and learns from tokens. These costs survive the reduction in Ridge work.

## 3. Fewer states do not automatically mean better predictions

Adjacent prefixes share most of their text and often the same sampled return. Keeping all of them supplies many rows, but less independent information than the row count suggests. Boundary selection can reduce redundancy and change which parts of an answer dominate the fit.

However, it can also miss an important moment inside a chunk. A single sign change can alter a solution. If that action lies between retained boundaries, the head receives less direct supervision about it.

There is also a weighting change. With equal token weights, a 1,000-token answer influences the fit more than a 100-token answer. Equal chunk weights replace that imbalance with one based on chunk counts. Equal answer weights would be a third objective.

Thus chunking can help, hurt or leave accuracy essentially unchanged. A cost saving with unchanged accuracy is already a meaningful result; no improvement in accuracy is required to justify the design.

## 4. Isolate fitting from credit assignment

There are two different interventions:

| Intervention | What changes? |
|---|---|
| Boundary-only fitting | Which examples train the value head |
| Chunk-level advantages | How rewards and value differences are combined for actor learning |

To isolate the first, fit two heads on the same answers, one using all tokens and one using selected boundaries. Evaluate both on the same held-out prefixes with the same reference values.

If we also change advantage computation, any actor-performance difference can arise from fitting, credit assignment or both. That is a useful system comparison, but it does not isolate the effect of using fewer regression rows.

## 5. Grouping time changes the equations

Let chunk $$j$$ start at token position $$\tau_j$$ and contain $$d_j=\tau_{j+1}-\tau_j$$ actions. Its discounted reward is

$$
\bar r_j=\sum_{k=0}^{d_j-1}\gamma^k r_{\tau_j+k}.
$$

The corresponding boundary residual is

$$
\bar\delta_j=\bar r_j+\gamma^{d_j}\widehat V(s_{\tau_{j+1}})
-\widehat V(s_{\tau_j}).
$$

At $$\gamma=1$$ with zero intermediate rewards, this becomes a difference between boundary values. A terminal chunk includes its outcome reward and uses zero terminal next value. These identities assume boundaries define valid decision points; using future answer text to construct features would still be leakage.

GAE introduces another clock. A trace parameter of 0.95 per token leaves weight $$0.95^{20}\approx0.358$$ after twenty tokens. A parameter of 0.95 per chunk leaves weight 0.95 after one twenty-token chunk.

The numerical parameter is the same, but its meaning has changed. Using token-duration-adjusted decay can align boundary trace weights, yet omitting within-chunk residuals still generally changes the estimator. Chunk-level GAE is not merely token GAE written more compactly.

## 6. What should happen to conditioning?

Nothing universal. Keeping fewer rows changes the Gram matrix. It can remove repeated directions, or remove observations that helped constrain a weak direction. Rank and the smallest eigenvalues may suffer even if prediction accuracy remains similar.

A chunk head can therefore have worse conditioning and comparable test error while being cheaper to accumulate. As [Article 3]({% post_url 2026-10-14-post-3 %}) explains, numerical sensitivity and predictive performance are distinct measurements.

## 7. Measure the saving at the right scale

Write total time schematically as

$$
t_{\mathrm{total}}=t_{\mathrm{generation}}+t_{\mathrm{features}}
+t_{\mathrm{head}}+t_{\mathrm{actor}}+t_{\mathrm{other}}.
$$

If head fitting accounts for 10% of the original time, making that component five times faster gives total time $$0.9+0.1/5=0.92$$ of the original: an 8% saving, not an 80% saving.

Likewise, fewer cached feature rows can reduce storage without lowering peak GPU memory if model weights, activations or reserved inference caches dominate. Report component costs and whole-system costs separately.

VinePPO provides a useful related design: estimate values with Monte Carlo continuations at reasoning-step boundaries. Its experiments motivate examining step-level credit assignment, but do not establish that boundary-only Ridge fitting must improve accuracy. [VinePPO](https://arxiv.org/html/2410.01679)
